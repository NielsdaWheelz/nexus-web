# strict lexical retrieval underestimates current publications

`services/search/sources.py:_CURRENT_TEXT` still uses bare
`lexical_revision = revision`. restored-corpus qualification13 estimated three
current state rows versus 485 actual; ordinary analyze did not repair the
column-to-column equality estimate. this helped select repeated chunk traversal.

an expression statistic plus `(comparison) IS TRUE` repaired the estimate.
qualification15 preserved all ordered winners, scores and passages while reducing
common/library retrieval from 11–13 seconds to 5.13 seconds. subsequent controlled
qualification18 measured 2.63–2.93 seconds through fresh admitted snapshots.
these are historical strict-query controls, not browser latency acceptance.

browser lexical retrieval now uses its separate native occurrence contract.
`semantic.py:nearest_chunks` now uses the corrected predicate and the owned
`content_index_states_lexical_current` statistic in unreleased0306; its complete
browser qualification remains open in the semantic recall issue. that does not
repair the distinct strict lexical query.

its eligibility, literal citation evidence, scores and deterministic passage
selection. no additional engine, compatibility reader or ranking change is
implied. do not revive the rejected scalar/materialization rewrites.
