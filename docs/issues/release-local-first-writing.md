# local first writing hard cutover

implementation is integrated; installed/mixed-device and capacity qualification
remain open. no deployment or production data deletion has been
performed. [specification](../local-first-writing-spec.md) owns the target.
this release replaces current online-first writing, not the media/download stack.

prerequisites:

- qualify selected sqlite binaries, native bridge, single-block editor, real
  firefox cold startup, existing samsung handset and the 100,000-block corpus.
- qualify authored node helper within the current api/host memory limits and
  snapshot streaming within the bff deadline. record actual results in the pr.
- communicate the accepted firefox forced-quit update boundary in the notes
  module: one online reopen may be needed if forced quit interrupts a waiting
  compatible shell update. normal quit and offline activation are qualified.
- preflight current corpus for semantic-key collisions, unsupported bodies,
  uncertain source provenance and encoded command-size limits; preserve data or
  stop with exact records. freeze conversion in one migration after actual head.
- prepare one paired backend/web/apk, wire revision, build assets and module/rule
  updates. no second protocol, runtime aliases or retained old write endpoints.

release procedure through existing deployment owners:

1. inventory every provisioned device/profile. owner approved coordinating
   format-breaking releases; synchronize each, confirm local commit and remote
   catch-up, then close it. future replicated releases drain cursors as well as
   uploads. unavailable device postpones cutover unless its disposition is
   explicitly resolved with the owner.
2. use the existing no-use window, stopped writers and verified backup. migrate
   all canonical content once, seed existing semantic identities and verify
   body/text/reference/annotation/order invariants. unknown original source
   generation stays null unless current exact-match proof exists.
3. deploy through `deploy/hetzner/deploy.sh`; pair the signed apk. provision the
   browser shell and complete local corpus on both devices. source downloads,
   player/progress state and account identity stay under their existing owners.
4. verify offline cold-open, local write/reopen and bidirectional synchronization;
   verify existing server tools use the same feed, and old authored routes/types
   are absent. failure is repaired forward under the existing release runbook.

resolved only after the exact paired release passes installed-device and deployed
qualification. temporary scenarios remain until final proof, then are deleted;
retain no permanent scenario suite. no age-based removal of pending changes,
causal state or devices is authorized.

cutover identity boundary: close every old client and reject its wire before
publishing the new graph. preserve every live resource and recoverable semantic
binding. old retired link ids retain only one endpoint; their already-deleted
pair cannot be recovered from current rows. old page teardown likewise deleted
its daily-date binding, leaving no recoverable date in the retired identity.
retire obsolete identity tombstones
atomically. recreating such an erased pair or day after cutover uses the new deterministic
id. this adds no historical recovery product and never discards an extant edge.

source-label conversion uses saved literal quotes and embed labels, plus compact
provable current owner/member admission paths. a source reached only through a
more complex grant/containment path may seed its literal ref as unavailable label
until a new legitimate capture refreshes it. lingering references never authorize
new private metadata. canonical writing and captures remain intact.
