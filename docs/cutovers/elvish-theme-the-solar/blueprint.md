# The Solar — implementation blueprint

Target: `data-theme="elvish"`, display name **the Solar**. Plan only; no product code changed by this document. Every line/path below was re-read against the working tree at `main` (42f33dc4fc).

---

## 1. Decision record

**D1 — Machine value `elvish`, display name "the Solar".** The attribute value is the wire format (cookie + `data-theme`); the room name lives only in Settings copy. Do not name the attribute `solar` — the design corpus, this blueprint and the fan-legibility of the CSS all key on `elvish`.

**D2 — Full-app theme, not a scoped skin.** `[data-theme="elvish"]` overrides the same ~34 semantic tokens the `[data-theme="light"]` block overrides (globals.css L182–220), and the whole app repaints. The oracle model (globals.css L284–297: nine `--oracle-*` tokens, zero semantic overrides, consumed by one route's stylesheet with a raw-hex exemption) is the wrong model — it exists because the Oracle is a *route*, not a room. Oracle stays exactly as it is and continues to nest correctly under an elvish `<html>` for the same reason it nests under light and dark today: it never reads a semantic token.

**D3 — Cookie union widens to three.** `AppTheme = "light" | "dark" | "elvish"` in `lib/theme/cookie.ts:3`, and the value guard at `cookie.ts:7` widens with it. That guard is the real gate: any other cookie value already returns `null` and falls to system. No migration, no versioning — a single-user prototype whose only stale cookie value is a valid one.

**D4 — "system" stays two-valued, and that is correct.** There is no `prefers-color-scheme: elvish`. The Solar is reachable only by explicit selection. The `@media (prefers-color-scheme: light) { :root:not([data-theme]) }` fallback (globals.css L223–263) cannot leak into it because the selector requires `data-theme` to be absent. Settings therefore shows four options — Study, Press, **Solar**, System — with System documented as "matches your OS, which only knows day and night." No auto-elvish, no time-of-day switch (final direction §10 already killed the hour-drifting canvas).

**D5 — `color-scheme: dark` declared inside the block.** Neither existing theme declares `color-scheme` anywhere (verified: zero occurrences in globals.css and layout.tsx). The Solar is the first, and it must be, or native selects, date pickers, autofill and the UA scrollbar arrows punch white holes through the canopy. Declaring it inside `[data-theme="elvish"]` only — do not retrofit light/dark in this cutover; that is a separate, unrelated change with its own visual diff.

**D6 — `theme-color` becomes cookie-aware.** Today `layout.tsx:36–39` exports a static `viewport` whose `themeColor` is a two-entry media-keyed array — it never reflects the cookie at all, so an explicit theme choice already leaves the mobile browser chrome mismatched. Replace the static `export const viewport` with `export async function generateViewport()` that reads the same cookie the layout already reads and returns a single `themeColor` string when the cookie is explicit, falling back to today's media array when it is absent. The layout is already dynamic (it awaits `readThemeCookie()` at L117), so this costs nothing new. The Solar's chrome colour is `#15201b`.

**D7 — the Solar's canvas hex does not go in `brand.css`.** `apps/web/src/app/brand.css` and `apps/web/src/lib/brand.ts` are both auto-generated by `scripts/build-icons.mjs` from the asterism SVG and are explicitly "do not edit by hand". `--accent` aliases `--brand-fg-on-dark`; the Solar's accent (`#c9a95f`) is close to but not equal to the brand gold and must be its own literal inside the elvish block. For D6's TS constant, add `SOLAR_BG = "#15201b"` to `lib/theme/cookie.ts` (hand-owned, already the theme module, and `.ts` files are outside the CSS literal scan). Brand identity — favicon, apple-icon, OG image, `manifest.ts` — stays Press-dark, per final direction §9.11.

**D8 — the sealed dossier document maps elvish → dark.** See §6, landmine L1. This is a decision, not a deferral: the third pre-authored stylesheet is S3-optional, the mapping is S0-mandatory.

## 3. Asset production plan

**Fonts — one family, two files, ~40KB.** Cormorant (SIL OFL, Catharsis Fonts), Google Fonts latin subset, weight 300 normal + 300 italic → `cormorant-normal-latin.woff2`, `cormorant-italic-latin.woff2`. Same acquisition path and byte range as the existing faces (EB Garamond is 44K/48K). `preload: false`; it never carries first paint. Everything else is already local: EB Garamond (reused as `--font-serif` for the Solar at zero new bytes), Inter, JetBrains Mono.

**Tengwar — zero runtime font bytes, by rule.** Tengwar Annatar (display) and Tengwar Telcontar (small) are installed **on the design machine only** and never enter the repo. Pipeline per inscription: compose the line → transcribe independently in Glaemscribe *and* Tecendil → diff; disagreement means the line is wrong, rewrite rather than fudge → set in the design-machine face → convert to outlines, hand-kern → export minimal `<path>` d-strings. Each entry lands in `elvishInscriptions.ts` recording: surface, Latin source, language, mode (Quenya tehtar-over-preceding *or* Sindarin mode of Beleriand — never mixed inside one inscription), both tool outputs verbatim, transcription date, reviewer. Consumers render `aria-hidden` inline SVG. Inventory: 4 inscriptions (reader chapter opener, empty state, colophon, one spare) + ~6 isolated tehtar for rule terminals + one cropped-glyph band strip used as pure geometry.

**SVG ornaments — data-URIs in `globals.css`, following the `--canvas-grain-image` precedent exactly** (percent-encoded, `<` → `%3C`, `#` → `%23`). Five assets: grain tile 320×320 (feTurbulence + six sub-pixel stars, one asset because the token holds one image); vine tile 240×12 (seamless — first and last path points share a y-value with horizontal tangents; verify the seam at 3 zoom levels before shipping); corner branch 48×48 (mirrored by `transform` into four placements); leaf terminal 10×10; tengwar band strip (baked, cropped, masked to fade at both ends). Data-URI is right for these four because they must be *token-swappable* and because keeping them in `globals.css` keeps the raw-literal count outside the allowlist at zero. The inscriptions go to TS instead: they are large, they carry provenance metadata, and they are per-surface rather than tiled.

Total new bytes: ~40KB fonts + ~6KB inlined SVG + ~15KB inscription paths. Zero effect on `check-bundle.mjs`'s 115KB First Load **JS** budget except the inscription module, which must be imported only by the surfaces that render it (never from a shared barrel).

## 6. Landmines & risks

**L1 — the sealed dossier stylesheets are the one place tokens cannot reach.** `MachineText.tsx` L36–124 holds two complete, hand-written stylesheets (~60 raw hex literals each) for the opaque-origin learning document. They are invisible to `check-css-tokens.mjs` (it scans `.css` only) and cannot use custom properties because the iframe is a sealed, opaque-origin document with no access to the parent's cascade. Combined with `DossierDocumentFrame.tsx:140–146` falling through to `prefers-color-scheme`, an OS-light user in the Solar gets a **white** dossier. Fix in S0 with the one-line mapping; a third stylesheet is a real S3 option and a real 60-literal maintenance cost.

**L2 — the token gate's own allowlist hides three real seams.** `media/[id]/page.module.css` (26 literals), `reader/textDocumentReader.module.css` (1, the find-highlight palette), plus the `oracle/**` and `atlas/**` path exemptions. The final direction claims "zero missed seams"; that is true of *unaudited* leakage but not of these four accounted-for files. Audit the 27 allowlisted literals during S0 and either tokenize them or write down, per literal, why the Solar may ignore it. Oracle and Atlas are deliberately their own rooms and stay.

**L3 — `mask-image` is new to this codebase.** Zero occurrences in `src/`. The entire ornament system rests on it. Author longhand (`mask-image` / `mask-repeat` / `mask-size` / `mask-position`) with `-webkit-` twins, and remember that the only browser the test lane exercises is Chromium — Firefox and WebKit differences will be found by eye, not by CI. `border-image` and `mask-border` are already ruled out by the direction and that ruling is correct.

**L4 — performance.** `filter: drop-shadow` is the single most expensive thing in the theme; it is confined to `:focus-within` on two element types and must never touch a surface that repaints per scroll frame. `--ornament: 0` in dense/virtualized lists is not a nicety — it is the frame budget. No `backdrop-filter` except the one modal scrim. The grain rides the existing `body::before` (`globals.css:328–337`) inside the `isolation: isolate` stacking context at L325; do not add a second full-viewport layer.

**L5 — FOUC is already solved; do not un-solve it.** `data-theme` is server-rendered from the cookie onto `<html>` (`layout.tsx:117,121`) with no client theme script, so there is no flash today. Anything client-computed (`--moon`, the session star seed) must therefore have a valid authored default in the block and only ever refine after hydration. Declare `--moon: 1` and let the effect narrow it.

**L6 — the session star seed must not regenerate SVG.** Rewriting `--canvas-grain-image` at runtime with a fresh data-URI is a large inline style, a hydration-mismatch risk, and a repaint of a fixed full-viewport layer. Seed instead by randomising `background-position` and a 90/180/270 rotation of the one tile in a client effect: a different sky, zero new bytes, no mismatch.

**L7 — reduced motion is a design constraint, not a CSS block.** The existing `prefers-reduced-motion` rule zeroes durations; it does nothing to keyframe animations you author yourself. Every Solar reveal must be a `transition` so that end states survive automatically. And this repo has been bitten by chrome that retreated too slowly (mobile reader scroll chrome, #155) — the instant-exit law is not aesthetic advice.

**L8 — the second literal gate.** `SettingsAppearancePaneBody.tsx:16`'s regex is the one that silently reverts the Solar to "System" on reload if forgotten. It is not covered by any type.

**L2 disposition (recorded at S0 build, 2026-09-03).** The allowlisted raw literals, per path, and why the Solar may ignore each:
- `media/[id]/page.module.css` — the `.readerThemeLight`/`.readerThemeDark` blocks are the reader's own theme axis (`ReaderTheme`, a separate user setting, deliberately two-valued). In the Solar, an open document's reading surface renders in the reader's own room — warm near-black by default — not green dusk. That is a decision, not a bug (final-direction §9.10); `.readerThemeElvish` is S3-optional and owes its own contrast proof. This qualifies the S0 acceptance sentence: "every surface is green dusk" means every *app* surface; the reader document body and its find-highlight palette (`textDocumentReader.module.css`) follow the reader axis.
- `oracle/**` and `atlas/**` — deliberately their own rooms; `[data-theme="oracle"]` reads no semantic token and nests correctly under any app theme.
- `brand.css` — generated identity, stays brand-dark (§9.11).

**§5 correction (found at S0 build).** The claim that the packaged offline bundle is unaffected is wrong for the *staleness* pass: `offline-reading/main.tsx` imports `@/app/globals.css`, so any edit to it invalidates `nexus-offline/source-manifest.sha256` and fails both `build-offline-reading.mjs --check` and Gradle's `verifyOfflineReadingAssets`. Every slice that touches `globals.css` must re-run `bun run build:offline-reading` and commit the regenerated bundle (the shelf itself stays pinned dark; the payload change is dead weight).

**L9 — consciously accepted single-user shortcuts.** The packaged offline shelf and the Android native chrome stay Press-dark. The PWA manifest stays brand-dark. `ReaderTheme` and `MachineDocumentTheme` keep their two-value unions. No cookie migration or server-side validation beyond the union guard. Tengwar correctness is frozen by hand at design time with no automated check beyond the absence-lint — the double-tool diff is a human ritual, and in a one-user prototype that is the right trade.
