## reviewed decisions

- retain object-first publication members. existing ingestion publishers must prepare stable ids and verified objects before their database publication transaction; no object i/o inside it.
- select vendor adapters before importing their sdk. upstream provider and kernel pins must change together; no dependency overrides. local upstream commits require publication before a reproducible remote build.
- retain natural composite publication member keys from the explicit spec; a surrogate uuid would add identity without a correctness benefit. this narrowly overrides the shared opaque-id preference.
- search/history defects are published by the persistent controller to the feature boundary. retry preserves add/workflow drafts.
- workspace layout recovery must be visible before deleting its local copy. startup offers a stored layout or preserves it for later. explicit navigation merges its deep link; resume keeps the chosen layout. cross-window last-write-wins remains arrival ordered.
- pending writes bind the expected account at the api boundary. a later login must not redirect old durable work into a new account.
- ordinary workspace state remains trusted local data, following the existing activity outbox. owned network acknowledgments are decoded and compared with the submitted layout.
- immutable index pages use fixed, format-bounded pages; callers relinquish arbitrary page sizes. raw member responses preserve the exact bytes and digest.
- native cursor migration preserves unknown provenance as unresolved. old locators are not applied to newly selected content; some older positions require explicit resolution.
- api admission defers request cancellation until the admitted thread, response, and outer database lifetime have completed. cancellation cannot lend out an occupied slot or close a live worker's session.
- provider and kernel commits are published on their respective `codex/bounded-workspace-imports` branches, solely to make immutable dependency pins reproducible. full dependency suites remain pending.
- the publication query surface is `post` for every body-bearing read: evidence, seek, associations, location, gutter, overview, bucket, preview, apparatus (+lookup/targets/text/location), highlight-summaries, highlights, embeds, section-context, resolve and find. `get` is kept for the reads that take no body: reader-publication, descriptor, index, units and assets. this deviates from the contract table's `get /reader-publications/{g}/evidence`; the arbitration and its price are recorded in the publication dossier and in the spec's recorded-deviations section.
- search's admission is not settled. `/search` joined the shared foreground read pool while the spec's own clause — "investigate the recorded search timeout with its real query plan" (oi-083) — was not done, so a 30 s statement-timeout query can now hold a reader slot. either the plan work lands before the release that admits search, or `/search` comes back out of the JSON pool and the deferral is recorded. this is open, not decided.
