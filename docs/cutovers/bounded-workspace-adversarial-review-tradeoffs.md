# bounded workspace adversarial review: stated trade-offs

every trade-off a fix package took, verbatim, grouped by package. none were absorbed silently; each names the cheaper choice it rejected. see bounded-workspace-adversarial-review.md for the ledger.

## P_x_ingest

- D_ingest_producers-9: I took the verifier's fallback (value-shaped floor + named refinement) rather than the stronger per-element attribute allowlist. Reason: `_EPUB_ALLOWED_SVG_ATTRS` was written for the inline sanitizer's small tag set; standalone SVG assets (covers, figures) carry far more elements and attributes, so imposing that allowlist here would silently strip legitimate artwork with no corpus evidence that the branch could produce. The floor restores exactly the screening strength the branch removed and is proven; the allowlist remains the right eventual posture and should be done with a corpus behind it.
- D_ingest_producers-10: `display.mode` for a forbidden target is `resolved` and for a deleted target is `failed`, because widening the mode literal lives in python/nexus/schemas/media.py and the web display-mode switch, neither of which is in my package. The user-visible lie ("Resolving embedded media" forever) is gone and `target.status` already carries forbidden/missing exactly, but the mode is a borrowed value until the schema is widened.
- D_ingest_producers-7: the planned winner is now recomputed from every discovery pass, which makes the id carried by `_XMediaLockSetChanged` dead for the single-post path (discovery overwrites it at the top of the next iteration, so the handler is a bare `continue`). I kept the payload because the thread path still uses it to grow `locked_existing_quote_ids` for the next attempt's fence. The pre-existing conflation there — a thread-winner id raised at x_ingest.py:319/:472 also lands in `locked_existing_quote_ids` — I deliberately left alone: separating it changes fence coverage and was outside the finding.
- D_ingest_producers-11: the restructure changes one error classification in a corner case. Previously a second redirect was rejected with "Too many redirects" before its Location header was read; now the first redirect's target is validated (denylist + DNS) before the second request, and a redirect returned by that second hop is rejected with the same message. A second-hop redirect to a denylisted host is still never fetched. No test asserted the old ordering.

## P_pdf_anchor_provenance

- Backfill source: `media_file.source_sha256`, not `reader_publication_artifacts.sha256`. At migration time 0229 has just created reader_publication_artifacts and it is empty, so the artifact digest is unavailable; media_file is the same object the artifact is later verified against, so the two agree by construction.
- Attribution rule is deliberately conservative and may leave some genuinely-unchanged anchors NULL: an anchor on a media with generation > 1 that is older than the last republication stays unattributed even if that republication was title-only and never replaced the binary. Distinguishing those would require a per-generation record of which publications installed new source bytes, which the schema does not keep. Over-refusing costs a manual reattachment; over-stamping would fabricate provenance, which the spec forbids ('never substitute current content beneath an old locator').
- Rejected the `source_verified` flag on PdfHighlightPaint and the `source_sha256 IS NULL OR = :digest` paint filter proposed by D_ingest_producers-2. Two verified findings conflicted here; D_history_map_evidence-2's verifier is explicit that the paint filter and digest match are correct and must not be weakened, and painting geometry authored against unknown bytes over the current binary is precisely the substitution the spec bans. The honest surface for those rows is the explicit disposition in the resolver plus the existing evidence-sidebar SourceUnverified reason, not a rectangle drawn on bytes we cannot attribute. It also keeps PdfHighlightPaint (schemas/highlights.py, not owned) unchanged.
- Rejected loosening `_find_duplicate_pdf_anchor` to treat a NULL-source anchor as a conflict candidate. Page/quad equality across two different binaries is not evidence of the same selection, so refusing a new highlight on the strength of an invisible, unattributable anchor would be the same unjustified equality claim in the opposite direction — and would leave the user permanently unable to highlight that region. After 0230 the duplicate guard sees every anchor whose identity is actually provable.
- `resolve_highlight_reader_target` is kept as a thin wrapper returning `.target` so the four non-owned call sites stay compiling and behaviourally identical. That leaves the new typed disposition consumed only by the proof until the caller changes in notes land; the alternative — changing the shared return type now — would break files this package does not own.
- The rewritten write-time match still asks Postgres for `substring(canonical_text ...)` on a TOASTed column, so a compressed value is decompressed up to the requested offset. What is eliminated is the three whole-document copies into CTE tuplestores. Making the cost fully page-local would require per-page text projection rows alongside reader_publication_search_sources (reader_publication_artifacts.py, not owned) — that is the step that would let the publication dossier qualify the late-match cost instead of leaving it 'unqualified'.
- The two new proofs are database-backed and could not be executed here (the allowed pytest scope is python/tests/kernel without a database). They were written against the current schema and the existing published_pdf_sources fixture and verified by parse/import only; the new match proof reuses that fixture's generation-2 text ('replacement') rather than duplicating ~35 lines of publication fixture code into a file this package owns.

## P_publication_schema_core

- D1_publication_core-V1: the fence is derived from background_process_wall_timeout_seconds + media_teardown_cleanup_grace_seconds rather than from a deadline threaded from each caller. That keeps prepare_reader_publication_member's signature unchanged (its callers in reader_publication_backfill.py, the ingest publishers and reader_publication_sources.py are outside this package) at the cost of one extra SELECT now() per member and a fence that is an upper bound on the attempt rather than the attempt's exact remaining budget. It is still a mechanism, not a global guess: every publication attempt runs inside a background job bounded by that wall timeout, so the fence cannot expire while the attempt can still commit.
- D1_publication_core-V1: retain_until is an optional keyword on reserve_storage_object_write rather than a required one. Making it required would have edited six call sites in files this package does not own. Documented as "omit it when the caller finalizes the write in its own bounded step", which is exactly what the existing ingest/email callers do.
- D1-2: kept one reservation per member. Collapsing to one per preparation requires prefix- or list-scoped cleanup semantics, which would duplicate storage_orphan_sweep inside storage_object_cleanup and would still be invisible to media_teardown's scalar storagePath read. I judged a second orphan sweep the wrong mechanism to build blind; the flood is reported instead.
- D1-2: I explicitly rejected dropping the reservation in favour of storage_orphan_sweep, even though its 86400s min age already makes a mid-preparation delete impossible. The reservation is also the only way media_teardown learns about in-flight preparation bytes (media_teardown.py:158-166), so dropping it would trade a fence for a 24-hour orphan window on every deleted media.
- D1-3: only the equality guard is applied. A title-only generation still copies reader_publication_units.canonical_text and reader_publication_search_sources.normalized_text/canonical_text, i.e. the whole document text, into the new generation. That remains a real retained-growth cost on every genuine title change; it is now paid only when the title actually changes.
- D1-6: making prepared required knowingly breaks seven test call sites in four files owned by another package (listed in notes). I took the contract fix because the owner is my file and the weakened invariant is the one the schema exists to enforce; the fallout is a test-design decision for the tests package.
- D1-7 / SPEC_coverage_global-9: three search-projection invariants are, as of this change, enforced by neither the database nor an explicit application defect, because their producer (reader_publication_search.py) is outside this package. The window is real and is reported in notes with the exact predicates. The alternative - asserting them at install_prepared_reader_publication, which merely calls install_reader_search - would have put the invariant at the caller instead of the owner.
- D_history_map_evidence-3: the LATERAL ... LIMIT 1 rewrite assumes a fragment id is owned by exactly one media, so any retained unit naming it yields the same media_id. That holds because fragments.id is globally unique and media-owned and the unit row copies it; if that ever stopped holding, the old DISTINCT would have returned several owners and the new probe returns one arbitrarily.
- D1-8: capture_current no longer retries anything. A transient object-store failure that escapes the per-object budget now fails the capture and is retried by the enclosing job (three attempts), rather than re-running the full preparation up to three times inside each of those. Net worst case drops from nine full preparations to three.

## P_publication_render

- D2-3: the finding's first-choice restructure (capture values, release the connection, read the object, then re-open a session from the route for the per-embed projection) requires the route to hand the service a session factory — python/nexus/api/routes/reader_publications.py is outside my package. I took the finding's own stated alternative: hold the snapshot across the object read, which is bounded by the storage client's configured connect/read timeouts. Cost: one pool connection is held for the duration of a bounded unit-object read on the embeds path. Benefit: the request keeps exactly the single REPEATABLE READ / READ ONLY snapshot the dependency advertises.
- D2-3: removed the second can_read_media call after the object read. Under one snapshot it can never differ from the authorization get_reader_publication_member_for_viewer already performed; it existed only because the release had ended the transaction. If a future change reintroduces a release there, that re-check must come back with it.
- D2-9: document_asset_ref and the page count are read in reader_publication_resolve.py by two direct ReaderPublicationArtifact selects rather than by extending ReaderPublicationPdfSource, because python/nexus/services/reader_publication_read.py is outside my package. That leaves the 'which artifact row is the PDF asset' predicate stated in two places (read.py:99-106 and resolve.py) until the consolidation in note 2 lands — strictly less duplication than before (the object fetch, SHA256 and JSON validation are gone) but not the ideal single owner.
- D2-4: the reservation is now an upper bound rather than the exact cursor the page will return, so a page can stop up to a couple of bytes below index_bytes. The exact alternative (the sibling highlights pagers' pattern of carrying each candidate row's real cursor) would need a continuation lookup per candidate occurrence; the bound costs one scalar aggregate per request and is provably safe because token length is monotone in the decimal width of both coordinates.
- D2-5: equal-offset ties now resolve to the EARLIER ordinal at all four sites. This changes section-context's answer for a point at a shared offset (the seeded shape now reports the zero-width 'image-heading' instead of the following 'chapter'), which is the dossier's stated rule and what find and navigation already did. The three other sites were already ascending, so find, navigation and source-range behaviour are unchanged.
- D2-7: I did not switch reader_node.py from os.environ['NEXUS_ENV'] to get_settings().nexus_env. The verifier downgraded that half to a preference with existing precedent (services/redact.py:74), and get_settings is lru_cached and validates the whole Settings model, so calling it from this adapter would make a reader-preparation helper fail wherever full app settings are absent. The duplicated 'local' default remains; if the settings owner should be the only reader of NEXUS_ENV, that is a separate, wider change.
- D2-1: reader_word_boundaries buffers the child's stderr in memory (subprocess.PIPE) instead of discarding it, and keeps only the last 4096 characters in the defect message. A pathological child could emit a large stderr before exit; this runs in worker preparation, which release qualification already sizes, and the alternative (DEVNULL) leaves a non-zero exit with no cause at all.

## P_enrich_schema

- D1-4: the deferred title is dropped from this attempt's merge rather than held by rescheduling the job. `RescheduleRequested` does not burn the retry budget (jobs/queue.py:1506-1519), so waiting for the descriptor would spin unboundedly if the preparation job is dead; committing the other fields is terminal and honest. The generated title survives in the durable step memo, so a replay/retry publishes it once the descriptor exists.
- D1-4: enrich_metadata does NOT enqueue `prepare_reader_publication` on the deferral, contrary to the finding's corrected_fix. Publication preparation is the publication owner's job (ops/reader_publication_preflight.py enqueues it), `enqueue_reader_publication` raises `ReaderPublicationBusy` for media in `pending` (which `_READY_STATES` admits), and handling that here would put a second owner of publication preparation inside the metadata task. Convergence is left to the preflight; the deferral is observable through the `metadata_title_deferred` log and the `publication_unprepared` job result.
- D1-4: the unprepared state is still recognized by catching the publication owner's `ApiError(E_MEDIA_NOT_READY)` rather than by a typed return, because reader_publication_artifacts.py is outside this package (exact change in notes). The catch re-raises every other code, and the alternative — querying `reader_publication_artifacts` directly from the task — would move publication semantics into a consumer, against docs/rules/codebase.md's module-boundary rule.
- D1-4: a partially-applied enrichment (title deferred, other fields accepted) still reports `status: success` with the title absent from `fields`; no new durable field was added to the checkpointed `_SuccessfulPublication` memo. The deferral is visible in the `metadata_title_deferred` log line only.
- STATIC_gates-10: `ReaderPublicationFindRequest` now re-declares `query`, `match_case` and `whole_word` (3 lines) instead of inheriting them, because removing the duplication properly requires extracting a scope-less base in epub_find.py, which is outside this package. The NFC/line-break normalizer is delegated, not copied.
- D_publication_routes-10: page-level uniqueness is enforced at validation time only. The producer builds pages with `model_copy`, which skips validators, so a producer defect is caught on the verify/read path (which is where publication is gated) rather than at write time.

## W_artwork

- Ladder rungs are [32,64,128,256,512,1024] rather than the finding's illustrative [128,256,512,1024]: every real fixed-size consumer (32, 40, 88, 128 px covers, and the player's up-to-352px art) keeps an exact or near-exact demand instead of being rounded up to 128, which would have quadrupled the residency each small thumbnail reserves. Worst-case over-reservation is bounded at 2x per axis; a full-range drag costs at most one read per rung crossed.
- No animation-frame coalescer was added. With the ladder an in-bucket resize costs one getBoundingClientRect and an early return, so the coalescer would buy only layout reads, and it would defer demand past the synchronous publication that the existing withdrawal proof (observeArtwork.browser.test.tsx, not in my package) depends on.
- Concurrent source reads are derived as floor(residentPixels / maxDimension^2) rather than a newly committed constant: artworkCapacity.ts is not in my package and no receipt bounds transient encoded bytes. The derivation is honest but UNQUALIFIED (4 under ARTWORK_CAPACITY, 1 in the small-limit proofs) and should be replaced by a measured transient-byte bound when the capacity experiment is re-run.
- Decode stayed single-flight, serialized through one promise chain, so only the network transfer overlaps. This preserves the decode/canvas/blob peak profile the existing receipts were taken under; the cost is that a fetched cover can wait behind another cover's decode.
- Starvation defense is pass-over-once (an overtaken demand becomes the exclusive next admission) rather than a skip-count threshold, to avoid inventing a count. The cost is bounded-wait over throughput: while a large passed-over demand waits for capacity, later small demands wait with it instead of overtaking.
- The residency budget still counts pixels only. The retained encoded derivative is now measured in the capacity receipt but is not reserved, so the committed budget still understates real retained bytes until the byte-denominated limit lands in artworkCapacity.ts.
- The capacity experiment's 16-consumer profiles now perform their source reads concurrently (maxSourceReads = 16 there), so readyMs and transient overlap in that receipt are not comparable to the previous serialized run.

Equality would have matched today's numbers and refused any future server that lowers its minimum; the field's name and the spec's 'update native and its reader bundle before switching package production' both read it as a floor. package_schema_version and reader_contract_version stay equalities, because native must install exactly the schema the server produces.

## K_native_store

- F-7 admission size: I gate on the installed row's `size_bytes` (which is `prepared.installedBytes`, the sum of installed members) rather than re-parsing the installed manifest, and I do NOT subtract bytes already present in a resumable `.migration` directory. That is conservative in the safe direction (it can refuse a nearly-complete resume on a device that is genuinely under the 512 MiB reserve) and avoids a full directory walk per installed package on every foreground reconciliation — the unbounded background I/O the finding itself objects to. For schema-1 packages the converted output can differ from the installed size (html is re-emitted as unit JSON), so the figure is an estimate of the copy, not a guarantee.
- F-7 free-space seam: I added a constructor parameter `freeSpaceBytes: (File) -> Long` defaulting to `File.usableSpace` rather than calling `android.os.StatFs` inline like the download lane. Reason: an inline StatFs makes the gate untestable without ShadowStatFs registration and would report 0 available bytes in seven Robolectric store tests owned by other packages, turning their conversions red. The seam follows the store's existing injection idiom (clock, ids, durability, verifiers) and measures the same quantity as StatFs.availableBytes.
- F-9 disposition: a 2xx acknowledgment that attests a cursor we did not submit is disposed as Conflict against that attested state (spec c: "otherwise expose the existing conflict choice") using the state the origin just returned, rather than issuing a second fetch as the finding proposed. The returned state is already strictly decoded and account/generation-checked, so a re-fetch would only add a round trip and a race. The anomaly is still reported as a defect.
- F-9 isolation breadth: the per-candidate catch is `catch (defect: Exception)`, not a narrowed type, because the defects it must contain include StrictJson/`NoSuchElementException` failures raised inside `matches()`. It carries justify-ignore-error, reports through the owner, and leaves the pending row's exact intent untouched for the next pass; only the authorization-denial sentinel is rethrown so one denial still fences the account.

## P_offline_python

- F_offline_python-1: I kept `ensure_offline_package_for_viewer` returning bool rather than a Ready|Preparing|Failed union. The union's only consumer would be python/nexus/api/routes/offline_reading.py, which the runtime package owns, and the spec's mint contract is '202 {reader_generation,status_path} until ready' with the typed failure on the status route - so the union would have changed the mint's wire contract, not just its types. A dead preparation therefore still answers 202 + status_path, and the client reads Failed on its next poll (which is the order OfflineReadingOriginClient.kt already uses). If the route owner wants the mint itself to answer Failed, the union is a small follow-up.
- F_offline_python-1: no explicit user-initiated repair path replaces the removed requeue. The spec says nothing about re-arming a dead preparation and forbids blanket retries, and operation-types.md calls a dead letter a loud terminal state, so Failed now stays Failed until an operator replays the job. The cost is that a transient dependency outage that burns all three attempts needs an operator, not a tap.
- F_offline_python-3: OfflineReadingPackageError defaults to reason="Integrity" instead of naming a reason at each of its ~80 raise sites. The default is the class's own meaning (the retained publication does not verify); only the bound and source-availability sites, which mean something else, name a reason. A silent consequence is that a producer-side grammar violation (e.g. an executable element that survived projection) is reported to the native as Integrity rather than Server - honest about permanence, but it attributes a server defect to the package.
- F_offline_python-3: a deterministic rejection still consumes all three Heavy attempts before dead-lettering, because the queue has no non-retryable terminal failure for a handler other than the resource-limit path. Bounded, but wasteful; classifying once and failing immediately would need a queue-level change outside this package.
- F_offline_python-4/RETIREMENT_hardcut-10: deleting python/tests/kernel/test_offline_reading_package_contract.py removed the Python side of the shared V1 corpus conformance. I ported the parts that still describe live contracts (revision-key oracle, entry-path grammar, manifest bounds/strict JSON, ZIP member-attribute rejection) onto the schema-2 producer, but the corpus's readerDocuments, validPackages, invalidPackageCases and invalidTransportCases sections now have no Python consumer - they are exercised only by the native decoder's Kotlin tests. That is the intended end state (the decoder retires the fixture), but until then those sections are unguarded on this side.
- F_offline_python-8: OFFLINE_ARCHIVE_MEMBER_KEY is now derived from OFFLINE_ARCHIVE_SCHEMA_VERSION. It is a stored value in reader_publication_artifacts.path, so a future schema bump changes the key that existing rows were written under. That is deliberate - a new schema is a new archive member, not a rewrite of the old one - but it means a bump must be accompanied by data reasoning, not just a constant edit.

## P_runtime_admission

- One deadline per permit, not separate work and transfer deadlines. The permit is explicitly one unit covering execution, serialization and body transfer, and the owner cannot observe the phase boundary without instrumenting send; two deadlines would have meant splitting the permit. The general/image pools share work_deadline_seconds and the package pool has its own package_transfer_deadline_seconds, because those are the two genuinely different response-size regimes.
- Deadline expiry is classified as a defect (RuntimeError), not another retryable 503. Per docs/rules/retries.md a bounded wait that exhausts is a defect by default, and by the time the deadline fires the response has usually started, so no error envelope could reach the client anyway. Consequence: a wedged client's request ends with a truncated response and a logged defect, which is the honest signal; if this proves noisy in the capacity run, the answer is a larger qualified deadline, not a softer classification.
- Two new required fields on ReadAdmissionLimits, no defaults.
